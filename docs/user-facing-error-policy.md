# 用户可见异常提示规则

## 目的

普通用户只能看到能理解、能采取行动的错误提示。HTTP 状态、供应商原始错误、中转站信息、队列名称、模型密钥、任务编号和内部堆栈只进入日志，不能直接显示在产品界面。

## 稳定规则

1. 后端使用稳定的业务错误代码描述错误原因，前端不能只根据 `409`、`502`、`Failed to fetch` 等表面现象猜测业务原因。
2. 前端通过统一的 `UserErrorCatalog` 将错误代码转换为标题、说明、用户动作和是否可重试。
3. 用户设备到本项目 API 的网络失败，与本项目后台到模型供应商的连接失败必须使用不同提示。
4. 自动恢复或自动修复仍在进行时，不向用户提前显示失败；自动流程最终停止后才显示最终异常。
5. 同一个业务错误在输入页、会话页、历史恢复页必须得到相同提示和相同操作按钮。
6. 未识别错误使用安全兜底文案，不显示原始 `error.message`。

## 必须区分的类别

| 类别                     | 用户提示方向             | 用户动作           |
| ------------------------ | ------------------------ | ------------------ |
| 用户网络不可用           | 网络连接异常，请检查网络 | 重试               |
| 生图供应商连接失败       | 生图服务连接异常         | 重新生成           |
| 生图供应商不可用         | 生图服务暂时不可用       | 重新生成           |
| 生图超时                 | 本次生成等待时间过长     | 重新生成           |
| 生图限流                 | 当前生图任务较多         | 稍后重试           |
| 生图未配置               | 生图服务当前不可用       | 联系管理员         |
| 返回无效图片             | 生图服务返回的图片无效   | 重新生成           |
| 商品原图无效             | 商品图片无法读取         | 更换图片           |
| 商品证据不足且程序可确认 | 商品图片不够清晰         | 更换图片           |
| 质检无法得出结论         | 图片检查未能得出结论     | 重新生成           |
| 需求有歧义               | 还需要确认一些信息       | 回答问题           |
| 主体最终不一致           | 未能保持商品主体         | 修改需求或更换图片 |
| 图片检查服务失败         | 图片检查服务暂时不可用   | 重试               |
| 未知系统异常             | 任务处理失败             | 稍后重试           |

需求理解服务还必须区分以下稳定错误码：

| 错误码 | 用户提示方向 | 用户动作 |
| --- | --- | --- |
| `REQUIREMENT_AI_TIMEOUT` | 需求理解等待时间过长 | 重新尝试 |
| `REQUIREMENT_AI_RATE_LIMITED` | 当前需求理解请求较多 | 稍后重试 |
| `REQUIREMENT_AI_SERVICE_UNAVAILABLE` | 需求理解服务暂时不可用 | 重新尝试 |
| `REQUIREMENT_AI_AUTH_FAILED` | 需求理解服务配置异常 | 联系管理员 |
| `REQUIREMENT_AI_NOT_CONFIGURED` | 需求理解服务尚未配置 | 联系管理员 |
| `REQUIREMENT_AI_CAPABILITY_UNSUPPORTED` | 当前模型不支持图片或结构化需求理解 | 更换模型或联系管理员 |
| `REQUIREMENT_AI_INVALID_RESPONSE` | 需求理解结果未通过程序校验 | 重新尝试 |

需求理解单次模型调用使用 `REQUIREMENT_AI_TIMEOUT_MS`，整轮（包括一次短退避重试和最多一次 JSON 格式修复）使用 `REQUIREMENT_AI_TURN_BUDGET_MS`。前端不自行判断超时，页面只展示后端最终持久化的稳定错误码。

队列连续投递失败达到后端上限后，必须显示“任务队列暂时不可用”类提示并允许重新尝试；投递仍在自动恢复期间只显示处理中，不提前伪装成最终业务失败。

## 代码位置

- 前端目录：`apps/web/features/generation/user-error-catalog.ts`
- 前端测试：`apps/web/features/generation/user-error-catalog.test.ts`

新增错误代码时，必须同步更新错误目录和测试，禁止在页面组件中临时拼接另一套用户文案。
