# 提示词优化产品规则

## 1. 产品定位

提示词优化是正式发送前的输入工具，不是会话消息，也不直接触发需求理解、生图或会话状态更新。

支持的输入：

- 只有文字；
- 文字和一张或多张当前有效图片。

不支持的输入：

- 只有图片；
- 文字和图片都为空。

## 2. 用户操作规则

1. 每次优化同时保留原文和优化稿，不覆盖用户原文。
2. 用户可以采用优化稿、恢复原文、换一种表达，或输入具体要求继续修改优化稿。
3. 换一种表达和按要求修改都创建新的优化版本，并关联父版本，不覆盖历史版本。
4. 优化完成不等于正式发送。只有用户显式采用优化稿并发送后，文字才进入正式会话、需求理解和生图链路。
5. 用户在优化后修改文字、图片角色、图片顺序、图片关系、图片设置或模型时，旧优化稿不能继续按原采用关系发送；用户需要重新优化，或去掉优化关系后按普通文字发送。

## 3. 上下文与图片规则

- 优化使用本轮输入文字、本轮明确附带的有效图片、图片角色与关系、图片设置和所选生成模型。
- 本阶段不自动读取完整历史对话。第三阶段只能补充与本轮任务直接相关的有限上下文，不能把整个会话无条件发送给优化模型。
- 图片只用于理解商品、场景、构图和当前编辑对象，不允许在没有文字目标时单独反推提示词。
- 图片必须属于当前用户和项目，并满足当前产品可用状态；未交付或被拒绝的生成候选不能进入优化输入。

## 4. 版本、幂等和采用关系

- 每次提交使用用户级幂等键。同一幂等键和完全相同请求复用原记录；同一幂等键对应不同文字、图片、操作、父版本、设置或模型时返回冲突。
- 子版本的父记录必须属于同一用户、项目和会话，状态为成功，且子版本输入文字必须等于父版本优化稿。
- 子版本必须继续使用父版本相同的图片、图片设置、生成模型和有限上下文快照；上述输入已经变化时必须重新发起首次优化。
- 优化记录只有 `processing`、`succeeded`、`failed` 三种状态。终态不可被迟到结果反转；完全相同的终态重放可以幂等返回。
- 优化开始时冻结当前会话状态快照。并发产生的新会话消息不能改变本次优化上下文；超时执行可由同一请求接管，旧执行迟到后不能覆盖接管结果。
- 一个成功优化版本最多只能被一条正式用户消息采用。
- 正式发送在同一数据库事务中校验并写入采用关系。采用失败时不能留下已创建的会话消息或任务。
- 正式消息幂等重放必须同时校验完整请求，不能用同一消息幂等键发送不同优化版本或不同内容。

## 5. 程序与 AI 的责任边界

程序必须验证：

- 文字非空、长度、图片数量和字段结构；
- 图片存在、归属、项目、角色和产品可用状态；
- 父子优化版本、幂等键和采用消息关系；
- 优化前后的输入修订是否变化；
- AI 返回结果非空、长度合法；
- 后续阶段中的明确数量、设置、图片引用和结构化结果是否合法。

AI 负责：

- 理解用户想表达的创作目标；
- 结合文字和图片补充有效、非模板化的视觉描述；
- 在不替用户新增关键业务意图的前提下改善清晰度、完整性和可执行性；
- 根据“换一种表达”或用户自由修改要求生成新版本。

程序不能声称已经证明 AI 完整识别品牌词、视觉主体或全部语义重点。用户始终可以对照原文和图片确认后再采用。

## 6. 阶段边界

- 第二阶段实现契约、持久化、幂等、版本链、输入修订和正式发送采用关系，不对外开放会留下未完成记录的优化接口。
- 第三阶段接入多模态优化 AI、有限上下文、模型能力配置、程序校验和一次格式修复，并在同一个请求生命周期内收口优化记录。
- 第三阶段接口失败时先持久化稳定错误码，再返回包含 `optimizationId` 的 HTTP 错误；客户端可通过查询接口恢复最终状态，不直接展示供应商原始错误。
- 第四阶段实现前端优化、对比、采用、恢复、换一种表达、按要求修改和输入变化保护。
