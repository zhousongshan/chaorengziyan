# 提示词优化产品规则

## 1. 产品定位

提示词优化是正式发送前的输入工具。它将用户的自然表达整理为更清楚、完整、适合下游生图模型执行的指令，但不直接触发需求理解、生图或会话状态更新。

支持：

- 只有文字；
- 文字和一张或多张当前有效图片。

不支持只有图片或文字、图片均为空。提示词优化不能替代正式需求理解，也不能在信息不足时自行推进生成。

## 2. 用户操作规则

1. 优化成功后，完整优化稿直接写入输入框，原文字作为上一版本保留。
2. 用户可以继续编辑当前文字、逐级撤回，或基于当前文字再次优化。
3. 每次再次优化都创建新版本并记录来源版本；用户手动修改后也允许从当前文字建立新分支。
4. 优化完成不等于正式发送。用户仍需发送当前输入，文字才进入正式会话和生图链路。
5. 图片、图片角色、图片顺序、图片关系、图片设置、模型、Agent 设定或会话状态变化后，旧优化版本不能继续按原优化关系发送。

## 3. 上下文与图片规则

- 优化冻结本轮文字、显式图片、页面图片设置、生图模型、Agent 设定和当前会话快照。
- 不无条件读取完整历史。候选图片只来自本轮显式图片、当前有效商品图/参考图/编辑基图、已选结果、最近可交付生成结果，以及用户明确引用轮次中的可交付图片。
- 图片候选必须属于当前用户和项目，并满足产品可用状态；失败、拒绝或未交付候选不能进入优化输入。
- AI 判断当前文字是否依赖图片，并只能从程序提供的稳定图片 key 中选择。
- 图片判断结果分为：`not_needed`、`resolved`、`missing`、`ambiguous`。
- `missing` 或 `ambiguous` 不生成优化稿，也不猜测目标；产品提示用户选择或明确图片。
- 没有图片依赖时，只结合当前文字、Agent 设定、当前有效需求和页面设置优化，不凭空补充图片事实。
- `product_source` 提供商品事实；`user_reference` 只提供场景、构图或风格；`edit_base`、`generated_result`、`selected_result` 表示可编辑画面，不能混淆角色。

## 4. 版本、幂等和发送关系

- 每次提交使用用户级幂等键。同一幂等键和同一完整请求复用原记录；同一幂等键用于不同请求时返回冲突。
- 来源版本必须属于同一用户、项目和会话且状态成功，但新版本文字可以是来源优化稿经过用户手动修改后的当前内容。
- 来源版本只表达版本血缘，不授权复用已经过期的图片、设置、模型、Agent 或会话快照。
- 每次优化冻结独立输入修订；迟到结果只有持有当前执行令牌时才能写入终态。
- 一个成功优化版本最多被一条正式消息采用。
- 正式发送在一个数据库事务中重新校验文字、图片、设置、模型、Agent 指令哈希和会话快照版本，并写入采用关系。
- 前端标记过期只用于即时交互；后端事务校验才是权威保护。

## 5. 程序与 AI 的责任边界

程序必须验证：

- 文字、字段、长度、图片数量和角色；
- 图片存在、归属、项目和产品可用状态；
- 会话、项目、Agent、快照和版本关系；
- AI 选择的图片 key 属于程序提供的合法候选；
- 图片判断状态与选择结果相容；
- 明确数量和比例没有被遗漏、改变、新增或写成超出产品及模型能力的值；
- 幂等、版本血缘、迟到写入和正式发送采用关系。

AI 负责：

- 判断当前文字是否包含图片指代；
- 在合法候选中选择被指代图片，或明确返回缺失、歧义；
- 结合文字、必要图片、Agent 设定和当前有效需求改善表达；
- 不改变用户明确需求的前提下生成自然、非模板化的完整优化稿。

程序不能证明 AI 完整理解了审美、品牌和全部语义重点。用户可以继续编辑、撤回或再次优化。

## 6. AI 节点与失败规则

1. 第一个节点完成图片判断和文字优化，输出结构化契约。
2. 程序校验失败时，第二个节点只修复 JSON、图片 key、图片状态、明确数量和比例。
3. 修复后再次校验；仍失败则记录稳定错误码，不使用无效结果。
4. 图片缺失和图片歧义是可操作的业务结果，不显示供应商错误或内部堆栈。
5. 接口失败时先持久化稳定错误码，再返回包含优化记录 ID 的错误，客户端可以查询恢复终态。
